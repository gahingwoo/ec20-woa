ec20-woa: Quectel EC20/EC25 (USB 2C7C:0125) on Windows 11 ARM64

Tested on one board: the COM ports and AT commands (QMI mode). Mobile
data does not work: MBIM and RNDIS were tried on firmware
EC20CEFILGR08A03M1G and pass no data. Keep the module in QMI mode
(AT+QCFG="usbnet",0) and never bind MI_04 in that mode. See README.md.

CONTENTS

  driver\usbser\   ec20-ports.inf + .cat   COM ports through the inbox usbser.sys (any usbnet mode)
  driver\winusb\   ec20-winusb.inf + .cat  WinUSB binding, for tools\ec20at.exe (QMI/MBIM mode only)
  tools\           PowerShell scripts, Ec20.psm1, ec20at.exe (ARM64)
  ec20-woa-test.cer                        the certificate this CI run signed with
  README.md

Neither package contains a driver binary. The catalogs are test-signed with
a certificate made for this one CI run, so its certificate must be trusted.

INSTALL (elevated Windows PowerShell, in the folder this file is in)

  Get-ChildItem -Recurse | Unblock-File
  Set-ExecutionPolicy -Scope Process Bypass
  .\tools\Install-Ec20Driver.ps1 -Variant Usbser -ImportCertificate

  Device Manager > Ports (COM & LPT) should then list three "Quectel EC2x
  serial port (usbser)" ports (NMEA, AT, modem), in every usbnet mode.
  This also removes an older ec20-ports.inf. Test:

  .\tools\Send-Ec20At.ps1 AT                 (expect: OK)
  .\tools\Get-Ec20Status.ps1

IF A PORT SHOWS CODE 10, OR OPENING IT FAILS

  .\tools\Install-Ec20Driver.ps1 -Variant WinUsb
  .\tools\ec20at.exe --list
  .\tools\Send-Ec20At.ps1 AT                 (the scripts use ec20at.exe now)

REMOVE

  .\tools\Install-Ec20Driver.ps1 -Variant None
